# QGC_KevinJiang v1.5.0

Release date: 2026-10-05

QGC_KevinJiang v1.5.0 is an internal Windows release for GRobot project members, based on QGroundControl v5.0.8. It retains the stable `QGC_KevinJiang` application identity and supports upgrading an existing installation while retaining user settings.

## Changes

- Add RTSP transport selection to the DeepShark four-camera panel: automatic (from the URL), TCP, or UDP. The setting applies to all RTSP channels and reconnects active video streams when saved, without editing individual URLs.
- Fix GStreamer receiver reference leaks, incomplete shutdown after clearing a URL, cross-thread state races, and video-size extraction.
- Move AI settings, process management, and detection overlays into the DeepShark custom plugin. Display detection overlays in the DeepShark video panel and retain compatibility with the previous overlay setting.
- Extend focused regression coverage for AI detection reception, RTSP transport selection, and video receiver lifecycle.
- Pin the event library to a revision compatible with the existing MAVLink dependency, preventing clean-build failures caused by updates to its floating branch.

## Installation and upgrades

Use `QGC_v1.5.0_KevinJiang-installer.exe`. Close QGC before running the installer. The installer retains the fixed application identity and invokes the previous uninstaller with user-data retention enabled. Manual removal of an earlier version is not required.

After installation, confirm version `1.5.0` under Application Settings → Help. The Help page reads the runtime application version; the standard release script synchronizes the application and installer versions.

## Known limitations

- Receiver defect fixes do not establish that intermittent field stutter has been resolved. Long-running, multi-stream RTSP operation still requires field validation.
- Python, CUDA dependencies, and AI model files are not bundled; configure them separately on each machine.
- RTSP URLs, gripper PWM limits, and joystick mappings remain device-specific.
- The release audit checks staged application startup and the upgrade contract; it does not replace real-device acceptance or an actual in-place installation test.
- The current workflow does not apply an Authenticode signature.
