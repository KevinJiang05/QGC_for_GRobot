# 当前 Debug 性能实测（2026-09-08）

## 结论

当前数据不支持继续进行大范围资源优化。建议先完成稳定性验收；若要继续改善启动体验，优先分段测量发起视频连接之前的初始化过程，不调整已经恢复工作的接收和解码参数。

## 条件与方法

- 基于 HEAD `2a97fb1ea` 加当前未提交的优化与 constWrapper 兼容修正；Debug EXE 构建时间为 20:27:18。
- 三路 1920×1080 视频，第四路停用，保留现场配置。最初窗口观察时三路均有画面。用户要求停止 computer-use 后，未再进行任何 computer-use 操作；用户手动最小化、退出，数据由 PowerShell 系统计数器及现有应用日志采集。
- 32 个逻辑处理器。CPU 用进程累计 CPU 时间差除以实际采样间隔，再除以 32；不是把单核百分比当作整机占用。
- 窗口展开 25 点、83.8 秒；整个窗口最小化到任务栏 20 点、68.7 秒。每点等待 2 秒，加上 CIM 查询实际约 3.4 秒。GPU 使用 Windows GPU performance counters 中属于 QGC PID 的数据；3D/Decode 取各引擎的最大值后计算采样均值，不累加成整机总 GPU 百分比。
- MiB = 1,048,576 字节。内存工作集、进程私有内存、GPU 共享内存是不同指标，不能简单相加。
- 资源采样使用原先普通运行的 PID 38108，未开启本次启动诊断日志。窗口展开阶段不保证持续获得键盘焦点，不能当作严格的前台交互压力测试。

## 是否继续优化

1. **资源占用：暂不继续大改。** 最小化后 CPU 低于整机 1%；现有工作集约 1.13 GiB，视频仍保持连接。若没有明确内存限制，先保护稳定性；暂停后台解码会改变后台行为和恢复体验，不默认引入。
2. **启动：可继续做小范围定位。** 发起连接之前约 5.8 秒，连接后首帧约 1.1 秒。初始化代码包含 GStreamer、插件、QML 窗口及其他管理器；目前未分段计时，不能归因给某一个模块，也不能承诺可以省掉多少秒。
3. **稳定性：优先于继续压资源。** 本次短时采样与一次启动不能替代连续重连、断流恢复和 30 分钟验收。没有进行代码改动、重编译或历史版本回退。

测量结束时 QGC 保持运行；这一次启动启用了诊断日志，下一次不带 `--diagnostics` 的正常启动会恢复普通日志级别。
