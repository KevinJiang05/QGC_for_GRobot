## 2. 已解决并验证的问题

### 2.1 Servo12 机械爪的手柄连续控制

目标效果：按住按键时机械爪连续向一个方向运动，松开后保持当前位置，而不是回到中间。

已验证的参数方案：

| 参数 | 值 | 说明 |
| --- | ---: | --- |
| `SERVO12_FUNCTION` | `187` | 将物理 Servo12 映射为逻辑 Actuator4 |
| `SERVO12_MIN` | `1050` | 一个方向的安全端点 |
| `SERVO12_MAX` | `1350` | 另一个方向的安全端点 |
| `SERVO12_TRIM` | `1200` | 启动初始位置，不负责松键保持 |
| `SERVO12_REVERSED` | `0` | Normal；方向不符时再按机械结构调整 |
| `BTN9_FUNCTION` | `116` | `actuator_4_dec`，向 1050 方向运动 |
| `BTN10_FUNCTION` | `115` | `actuator_4_inc`，向 1350 方向运动 |
| `BTN9_SFUNCTION` | `0` | Disabled |
| `BTN10_SFUNCTION` | `0` | Disabled |

运动速度由 `ACTUATOR4_INC` 调整；当前经验推荐值约为 `0.180`。数值越大动作越快，首次调整应小步修改并短按测试。

不要用以下方案替代：

- `Gripper Open/Close`：它是另一套夹爪命令语义，不满足本项目按住增减、松手保持的要求。
- `actuator_4_min/max_momentary`：松开后会回到中间位置。
- `SERVO_RATE`：这是 PWM 输出刷新率，不是此控制方式的主要速度参数。

详细成员操作说明见：`docs/research/problem/Servo12机械爪手柄配置说明.md`。

### 2.2 ArduSub 4.8 参数元数据和手柄动作 UI

旧版 QGC 对定制 ArduSub 4.8 的参数元数据适配不足，导致：

- `SERVO12_FUNCTION=187` 等新枚举在 UI 中不可见；
- `actuator_4_inc/dec` 无法正常出现在按钮分配列表；
- 参数尚未下载完成时，按钮列表可能错误地全部显示为最后一个 QGC 动作，例如 `Gimbal Yaw Follow`。

已完成：

- 加入 Sub 4.8 参数元数据及版本选择支持；
- 保留可表示的有效枚举项，不再因个别不兼容枚举而清空整张列表；
- 手柄按钮列表等待参数准备完成后再刷新；
- 修正固件动作索引和 QGC 动作索引混用导致的错误显示；
- 9/10 号键可以在 UI 中选择 `actuator_4_dec/inc`。

按钮分配页面出现两列是正常设计：

- 左列是普通按钮功能；
- 右列是按住 `shift` 后的换挡功能（`BTNn_SFUNCTION`）。

本项目不使用换挡动作时，右列保持 `Disabled`。左列除实际需要的按键外可以设为 `No Action`；此前确认 5 号键用于 `shift` 时应按现场需求保留。

### 2.3 推进器直发 PWM 与舵机点动分离

此前扫描向导把推进器测试、物理 SERVO 直发和普通舵机点动混在一起，无法同时满足两类硬件需求。

现已分成三条路径：

1. `Motor Test`：飞控原生推进器测试。
2. `推进器直发PWM`：按物理 SERVO 输出编号发送指定 PWM，不按 `SERVOx_FUNCTION` 映射，不等待 Motor Test 冷却；结束回到 1500 PWM。
3. `舵机点动`：按物理 SERVO 输出编号发送独立 PWM；校验 `SERVOx_MIN/MAX`，结束回到该通道的 `SERVOx_TRIM`。

两种直接输出都会临时备份并禁用该通道的 `SERVOx_FUNCTION`，完成后恢复原值；异常情况下保留恢复记录。使用前仍须确认飞控上锁、设备固定、周边无人和无障碍物。

## 3. 已分析但尚未完全解决的问题

### 3.1 多路 RTSP 启动时偶发缺一路及 Qt QML 断言

现象：

- 程序刚启动时，偶尔只有部分摄像头进入播放；点击“全部重连”后通常可以恢复。
- Debug 版曾多次触发 Qt 6.8.3 断言：`qv4qobjectwrapper.cpp` 第 1511 行，`ASSERT: "constWrapper"`。
- 某些成员电脑上程序启动无响应，调整/禁用部分视频或硬件解码设置后可以启动。

已完成的缓解：

- 改进部分多路 RTSP 启动和重连处理；
- 在“应用设置 → 视频”中显式显示“视频解码优先级”，即使 QGC 内建视频源被禁用也可修改；
- 可以在默认、软件和硬件解码策略之间切换以适配显卡/驱动环境。

当前结论：该问题只能认为“降低概率、提供回退设置”，不能认为根因已经彻底解决。Qt 断言和不同显卡/驱动/GStreamer 环境仍存在兼容性风险。后续若复现，应保存崩溃转储、启动日志、解码优先级、显卡型号/驱动版本和具体 RTSP 通道状态，避免仅凭截图继续修改 QML 生命周期逻辑。

### 3.2 水下推进速度偏慢

现场现象：

- 25% 到 50% 时能听到推进器噪音明显增加；
- 50% 到 75%、75% 到 100% 时声音变化不明显；
- 底层观察到 50%、75%、100% 对应的控制输出仍在继续增加，因此没有证据表明 QGC 把输出硬限制在 50%。

未解决方向：

- ESC 标定或有效输入范围；
- 供电电压、电源限流、线损；
- 推进器/桨叶型号、方向、安装和水动力负载；
- 飞控输出映射与实际推进器对应关系；
- 推进器或 ESC 在高指令区间已经饱和。

曾看到约 `2.223 V、0.06～0.07 A` 的飞控遥测，但机器没有电池，使用外部电源直接供电，也没有确认安装有效的电压/电流传感器，因此该数据不能作为整机实际供电或功率证据。QGC 不能仅凭 PWM 推算真实功率。后续需要用电源侧仪表或钳形表测量电压、电流及是否限流。

### 3.3 实时功率显示能力

QGC 可以显示飞控上报的电压和电流，并据此计算功率，但前提是机器安装并正确配置了有效的电压/电流传感器。当前机器的供电架构下，已有遥测读数明显不可信，因此目前不具备可信的实时整机功率显示能力。

## 4. 当前未解决的飞控网络连接问题

### 4.1 最后现场状态

更换到另一台机器人后，USR-M0 能发现设备，QGC 无法出现载具。

USR-M0 已读取到的配置：

- 设备 IP：`192.168.1.200`
- 子网掩码：`255.255.255.0`
- 工作模式：`TCP Server`
- 本地端口：`4019`
- 串口：`57600 / 8N1`
- TCP Server 最大连接数：`4`
- “踢掉旧连接”：关闭

本机底层证据：

- 有线网卡同时配置了 `192.168.1.5/24`，到设备的路由正确；
- Ping 两次均成功、无丢包；
- USR-M0 调试程序成功建立到 `192.168.1.200:4019` 的 TCP 连接；
- 当前 Debug QGC 也成功建立到该端点的 TCP 连接；
- 额外第四个 TCP 客户端被动监听 4 秒，`Connected=True`，但 `ReceivedBytes=0`；
- QGC 同时能建立 RTSP 连接，说明程序本身并非整体无响应。

因此已经排除：

- PC 到串口服务器的基本网络不可达；
- 4019 没有监听；
- QGC 完全没有发起 TCP 连接。

当前判断：`飞控串口 → USR-M0 → TCP 4019` 没有任何 MAVLink 输出。随后现场确认飞控所有指示灯都没有亮，最优先根因是飞控未供电或供电链路故障，而不是 QGC 软件配置。

当前机器已关闭电源，未发送任何飞控、舵机或推进器控制指令。

### 4.2 USR-M0 独立“网络数据调试”窗口说明

该窗口主要提供发送模板，本次版本中没有适合观察持续接收字节流的区域。窗口底部“已经连接到 192.168.1.200”只证明 TCP 握手成功，不能证明串口侧收到飞控 MAVLink。此前要求在该窗口观察持续接收内容是不准确的，已经改用底层被动 TCP 读取验证。

### 4.3 明天建议的排查顺序

1. 保持主电源关闭，检查飞控供电输入、稳压模块输出、保险丝、插头、接线极性和地线。
2. 先仅用 USB 连接飞控：确认指示灯是否亮、Windows 是否枚举串口、QGC 是否能通过 USB 识别飞控。
3. 如果 USB 也不亮或不枚举，继续硬件供电/主板故障排查，不修改 QGC。
4. 如果 USB 能连接，先只读确认 USR-M0 实际接入的是飞控哪个串口（通常为 TELEM1 或 TELEM2），再核对对应参数：
   - `SERIALx_PROTOCOL = 2`（MAVLink2）；
   - `SERIALx_BAUD = 57`（57600）。
5. 检查物理串口接线：飞控 TX 接 USR RX、飞控 RX 接 USR TX，并确保共地。
6. 硬件恢复后关闭 USR-M0 独立调试连接，给飞控和串口服务器上电，再启动 QGC。
7. 在仓库根目录运行无侵入诊断：

```powershell
powershell -ExecutionPolicy Bypass -File .\tools\diagnostics\check-grobot-link.ps1
```

8. 若状态为 `QGC_TCP_ESTABLISHED` 但仍无载具，再做短时间被动字节监听并寻找 MAVLink HEARTBEAT；不要把 TCP Established 当作飞控已经连接。
9. 在飞控供电、MAVLink 心跳和载具识别恢复前，不进行解锁、舵机或推进器动作测试。
