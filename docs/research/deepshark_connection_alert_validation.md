# 异常断联预警：第一版实施与验证

日期：2026-09-08。当前提供 Debug 程序，现场验收由操作人员完成。

## 使用

设置 → 视频 → 异常断联预警。修改立即生效并自动保存。监测所有启用、有视频地址且未手动停止的 DeepShark 视频，以及当前飞控的主组件心跳。没有全部就绪时保持等待，不把初始未连接作为突然断联。

| 设置 | 默认值 | 可调范围 |
|---|---|---|
| 总开关 | 开 | 开 / 关 |
| 重复提示音 | 开 | 开 / 关 |
| 警报音类型 | 短提示音 | 短提示音 / Hi-Low 警笛 |
| 视频无新帧超时 | 3 秒 | 2–30 秒 |
| 飞控心跳超时 | 4 秒 | 2–30 秒 |
| 初始稳定连接时间 | 10 秒 | 3–60 秒 |
| 恢复确认时间 | 5 秒 | 2–30 秒 |
| 声音重复间隔 | 3 秒 | 2–30 秒 |

检查周期 0.5 秒，调度与采样会使实际提示时间略晚于设置阈值。飞控直接监听主组件心跳，视频观察解码 sink 的累计帧进度；不修改原有心跳失联判定、视频 watchdog 或飞控参数。

预警位于顶部状态栏，在模式/解锁按钮组与右侧品牌标志之间，不再占用视频面板空间。单行显示状态，过长文字省略；鼠标悬停不弹提示，点击展开详情和确认静音按钮。窄窗口收起品牌标志，并保留左侧状态按钮横向滚动，避免相互覆盖。异常时显示红色提示及具体信号；确认只静音，不隐藏尚未恢复的异常。新增另一种故障会再次提醒。持续恢复后，未确认的记录保留为黄色提示；确认后正常显示监测状态。事件也进入现有最近事件列表，并通过 `qgc.deepshark.connectionalert` 输出日志，不包含视频地址或凭据。

监测对象由应用持有。显示地图、隐藏面板和最小化窗口不会停止计时。手动停止视频只豁免该路；手动重连给该路 5 秒宽限，已有报警时不再豁免；自动重连不会取消报警。通过工具栏关闭飞控，或通过连接设置主动断开/删除最后一条飞控链路，重新等待就绪，先前未确认的事故仍可见。

声音测试播放当前选择的声音。新增 Hi-Low 警笛采用 960/640 Hz 每 0.4 秒交替、每段共 1.6 秒，并增加谐波与数字信号幅度；原短提示音仍为默认值，选择自动保存。切换时停止旧音，下一次测试或报警使用新音。两种声音均遵守本预警声音开关、应用总静音及系统音量，不依赖中文语音。换设备后需要人工确认实际可听见。总开关关闭会清除当前预警，重新打开后重新建立初始稳定状态。

## 自动验证

- `DeepSharkConnectionMonitorTest`：覆盖初始稳定期与中途抖动、视频/心跳独立超时、同时故障、静音与新增故障、恢复确认、主动断开/停用、主开关、receiver 重建、真实 Vehicle 信号接线及主组件过滤、设置保存读取与边界值、已有报警在重新建立监测期间继续提醒。
- 新设置和横幅实际创建，检查 QML 引擎没有警告；视频设置、连接设置及飞行视图组件进行 QML 加载验证。
- `DeepSharkVideoControllerTest`：原有视频资源重建、垃圾回收和状态行回归。
- 构建及上述两组测试日志：`build-debug-ai/connection-alert-final-build.log`、`build-debug-ai/connection-alert-final-test.log`。
- 顶栏位置和双音色更新的构建/测试日志：`build-debug-ai/connection-alert-toolbar-build.log`、`build-debug-ai/connection-alert-toolbar-test.log`。增加音色设置持久化、无效值边界以及顶部工具栏 QML 加载检查；两组测试通过，实际屏幕与扬声器表现仍由用户手动验收。
- 额外运行曾发现 `VehicleLinkManagerTest` 崩溃，历史日志为 `build-debug-ai/connection-alert-test.log`。随后按用户要求修复了 MockLink 线程竞争和摄像头晚到回调问题，链路及摄像头回归已通过，详见 [修复记录](../audits/mocklink_disconnect_fix_2026-09-08.md)。

本次还发现旧 Debug 构建目录的 MSVC 包含文件前缀乱码，使 Ninja 漏记头文件依赖，并导致旧测试对象与新增视频控制器字段布局不一致。修正了构建目录内生成的编译器前缀，重新编译相关对象；Ninja 已能记录依赖，视频测试随后通过。未修改全局工具链配置。

## 人工验收与边界

在干燥台架上确认：稳定连接后进入监测、单独停止视频源、单独中断飞控数据、同时中断、恢复、确认静音后出现新故障、最小化窗口仍发声、修改设置后重启仍保留。使用“声音测试”确认扬声器实际输出，并检查小窗口中横幅与视频布局。

自动测试不证明实机报警延迟和声音设备可用。已知链路模拟崩溃已单独修复；正式分发仍需标准 Release 打包校验及安装验收，不能把 Debug 回归通过等同于安装包验收通过。

断联提示不能确认进水，也不能用信号在线证明机器健康。持续发送重复图像的摄像头故障不在第一版检测范围内；进程卡死时不能保证及时报警。检测到自身计时停顿超过 5 秒时标记监测中断并重新等待新数据，不将其直接诊断为设备故障。没有增加自动断电或飞控动作。
