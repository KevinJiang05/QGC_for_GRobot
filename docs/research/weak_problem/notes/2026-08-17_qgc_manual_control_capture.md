这证明 Xbox 油门轴经过 QGC 后被连续编码为 `MANUAL_CONTROL.z`，目标系统、字段、方向和中位值均符合 ArduSub 4.8 的接收契约。没有发现 QGC/固件字段错位、按钮误触或 QGC 将油门固定在中位的情况。

## 固件幅度换算

当前运行时 `PilotGain=0.5`，参数 `JS_THR_GAIN=1.0`。固件计算：

```text
throttleScale = 0.8 * 0.5 * 1.0 = 0.4
throttleBase  = 1500 - 500 * 0.4 = 1300
RC override   = z * 0.4 + 1300
```

对应结果：

| QGC `z` | 固件内部油门 RC override |
| ---: | ---: |
| 500 | 1500 us |
| 604 | 1542 us |
| 772 | 1609 us |
| 823 | 1629 us |
| 1000（理论满量程） | 1700 us |

因此按上游源码推导，本次实际操作最高应请求到约 `1629 us`；即使 QGC 发到满量程 `z=1000`，当前 50% PilotGain 下也应只到约 `1700 us`。但抓包发生在未解锁状态，没有取得电机输出随 PilotGain 变化的证据，不能据此认定它就是动力不足根因。

## 当前结论

1. QGC 与 ArduSub 4.8 的手柄消息契约兼容。
2. Xbox 油门输入能够正常进入 QGC 并发送到飞控。
3. 现场观察显示 PilotGain 50%、75%、100% 时推进器声音和出风大小完全不变，这与源码公式的预期不一致。
4. 下一步必须同步记录 PilotGain、QGC 输入和解锁状态下的 `SERVO_OUTPUT_RAW`，判断增益变化是否真正到达电机输出；在取得该证据前不再把 PilotGain 视为根因。
