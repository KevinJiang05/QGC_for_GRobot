# 推进器动力不足排查记录

## 1. 目的与范围

本文用于持续记录 GRobot 推进器动力不足问题的证据、推测、测试过程和结论。

当前范围包括：

- QGroundControl 手柄输入链路；
- ArduSub 参数、混控和推进器输出链路；
- FlyingRC H7Wlite V2 板级 PWM 输出；
- ESC 输入信号以及高负载时的电源侧表现；
- 固件包的静态审查和必要时的版本对照。

在获得实测证据前，不把问题直接归因于固件，也不通过盲目刷写或恢复默认参数进行试错。

## 2. 当前环境

记录日期：2026-08-17

已知飞控与固件：

- 飞控目标板：`FlyingRC_H7WliteV2`
- MCU：STM32H743
- 固件：`ArduSub V4.8.0-dev (f3a6fa9d)`
- 固件文件：`software/ArduSub_custom_f3a6fa9d_FlyingRC_H7WliteV2_with_bl.hex`
- 固件 SHA-256：`4FF2579C7A04B1617D399758EFCEB3994E3EDCC23060FB99F3D260739E5609BD`

问题现象目前只确认到：推进器在高输出区间表现为速度或动力偏弱。尚未取得本次排查所需的飞控参数导出、DataFlash 日志、MAVLink 日志和物理 PWM 测量。

## 3. 已确认事实

### 3.1 固件包结构

对 Intel HEX 做了只读解析：

- 共 94,688 条记录；
- 所有记录格式及校验和正常；
- 有效数据连续覆盖 `0x08000000` 至 `0x08171C6B`，共 1,514,604 字节；
- `0x08000000` 存在启动加载器向量表；
- `0x08020000` 存在 ArduSub 应用向量表；
- 固件内嵌版本字符串为 `ArduSub V4.8.0-dev (f3a6fa9d)`；
- 固件内嵌板卡字符串为 `FlyingRC_H7WliteV2`。

因此目前没有证据表明该 HEX 文件发生截断、文本记录损坏或烧录镜像拼接错误。

### 3.2 对应源码提交

提交 `f3a6fa9d` 的上游标题为 `AP_HAL_ChibiOS: add FlyingRC H7Wlite V2`，主要内容是新增该飞控的板级定义、启动加载器和说明文件。目前没有证据表明这个提交专门修改了 ArduSub 推进器推力算法。

### 3.3 参数不在当前 HEX 镜像内

板级定义使用 `STORAGE_FLASH_PAGE 14`，STM32H743 上对应的参数存储区域约从 `0x081C0000` 开始；当前 HEX 数据结束于 `0x08171C6B`。

因此，这份 HEX 不能反映飞控当前实际保存的参数。判断当前限幅状态必须从已连接飞控导出完整参数。

### 3.4 板级 PWM 分组

板级定义中的输出分组如下：

| 物理输出 | 定时器 |
| --- | --- |
| PWM 1–2 | TIM8 |
| PWM 3–6 | TIM5 |
| PWM 7–10 | TIM4 |
| PWM 11–12 | TIM15 |
| PWM 13 | TIM1 |

同一定时器组内混用不兼容的输出协议或输出频率可能造成配置冲突，后续需要结合实际推进器接口映射检查。

### 3.5 QGC 与固件兼容性核对

已通过独立 MAVLink 连接读取运行中的飞控，结果如下：

```text
HEARTBEAT: MAV_TYPE=SUBMARINE, MAV_AUTOPILOT=ARDUPILOT, MAVLink 2
AUTOPILOT_VERSION: ArduSub 4.8.0, custom version f3a6fa9d
PARAM_VALUE: 1256/1256 参数完整收取
```

QGC 工程内包含 `Sub-4.8/apm.pdef.xml` 参数元数据，且实际连接已成功完成心跳、参数传输、`AUTOPILOT_VERSION` 请求和 `NAMED_VALUE_FLOAT` 解析。因此没有发现 QGC 与该固件之间的协议级不兼容或版本识别错误。

手动控制字段逐项对照如下：

| QGC 发送 | ArduSub 4.8 接收 | 结论 |
| --- | --- | --- |
| `x = pitch * 1000` | `x` 用于 pitch | 一致 |
| `y = roll * 1000` | `y` 用于 roll | 一致 |
| `z = throttle(0..1) * 1000` | `z` 按 0..1000 解释 | 一致 |
| `r = yaw * 1000` | `r` 用于 yaw | 一致 |
| `buttons` 低 16 位 | 固件处理低 16 位按钮 | 一致 |

因此目前不能把动力不足归因于 QGC/固件不匹配。需要区分“协议兼容”和“输出幅度配置”：固件在 `transform_manual_control_to_rc_override()` 中固定使用 `0.8 * gain * JS_THR_GAIN` 缩放升沉。当前运行时 `PilotGain=0.5`、`JS_THR_GAIN=1.0` 时，满量程升沉理论上只得到约 `1300–1700 us`；这是固件的有意增益限制，不是 QGC 解析错误。

### 3.6 电源遥测限制

板级默认电池标定包含 `HAL_BATT_VOLT_SCALE 11.0` 和 `HAL_BATT_CURR_SCALE 40.0`。项目此前已记录“当前飞控电源遥测不可信”，所以不能只凭 QGC 显示值排除高负载压降、电流限制或供电链路问题。最终应以电源侧仪表为准。

## 4. 当前推测及优先级

以下均为待验证假设，不是最终结论。

### H1：运行时摇杆增益限制了手动控制输出（代码路径成立，但实机现象不支持其为根因）

该版本源码默认值为：

```text
JS_GAIN_DEFAULT = 0.5
JS_GAIN_MAX     = 1.0
JS_GAIN_MIN     = 0.25
JS_GAIN_STEPS   = 4
JS_THR_GAIN     = 1.0
```

源码中前进、横移和偏航输入使用 `0.4 * gain` 缩放，升沉输入使用 `0.8 * gain * JS_THR_GAIN` 缩放。在默认 `gain = 0.5` 时，满量程输入可能只形成约 `1300–1700 us` 的控制范围，而不是完整的 `1100–1900 us`。

待验证：

- 当前 `JS_GAIN_*` 和 `JS_THR_GAIN` 参数；
- 运行时 MAVLink `NAMED_VALUE_FLOAT` 中的 `PilotGain`；
- 手柄满量程时 `MANUAL_CONTROL` 输入是否真正到达满量程；
- 手柄满量程时各推进器的 `SERVO_OUTPUT_RAW` 或 DataFlash `RCOU` 输出。

已完成的只读核对：参数快照中 `JS_GAIN_DEFAULT=0.5`、`JS_GAIN_MAX=1.0`、`JS_GAIN_MIN=0.25`、`JS_THR_GAIN=1.0`；运行时 `NAMED_VALUE_FLOAT PilotGain=0.5`。通过按钮位 11/12 调整该运行时增益时，飞控回报从 `0.5` 变为 `0.75` 再恢复 `0.5`，说明 QGC 的按钮与固件增益通道是连通的。

QGC 上行 TCP 抓包进一步确认：共解析 569 条 `MANUAL_CONTROL`，油门 `z` 从中位 500 上升到最高 823，`x/y/r` 均为 0、按钮为 0，且没有 MAVLink 解码错误。Xbox 与 QGC 的发送链路正常。按上游源码公式，本次最高输入在 50% PilotGain 下应换算为约 `1629 us`，但这只是源码推导，尚未由解锁状态下的 `SERVO_OUTPUT_RAW` 或物理 PWM 证明。

现场实测反证：PilotGain 从 50% 调到 75% 再调到 100% 时，推进器声音和出风大小完全没有变化。因此不能把 PilotGain 限幅认定为动力不足根因。需要验证运行固件是否真的按该变量改变电机输出，或者增益变化是否被后级混控、输出限幅、板级 PWM/ESC 输入范围覆盖。

后续直连定量测试已证明增益进入实际软件输出：固定 `MANUAL_CONTROL.z=600` 时，PilotGain 50/75/100 对应的 `SERVO4/5/7/9_RAW` 分别稳定为 1460/1440/1420 us。飞控计算与增益链路正常；结合现场推进器表现无变化，故障边界已下移到 `SERVO_OUTPUT_RAW` 之后。注意该消息是软件命令值而不是物理引脚回读。

示波器与 QGC 自研 PWM 直发功能的后续验证表明：QGC 直发的 PWM、飞控报告值和物理输出引脚的实测脉宽一致，正常控制中的 PilotGain 限幅也确实反映到物理波形。至此可基本排除 QGC/ArduSub 消息不兼容、增益未实现、混控未生效、板级定时器未输出以及软件值与引脚波形不一致等方向。剩余故障边界位于飞控 PWM 引脚之后，优先检查 ESC 输入端点/协议、ESC 响应曲线以及负载下的推进器和供电表现。

针对电流/电压限制的参数复核结果：`MOT_BAT_CURR_MAX=0`、`MOT_BAT_VOLT_MIN/MAX=0`，电池低压/临界阈值及 failsafe 动作也均为关闭值；未发现已启用的电流限幅配置。`MOT_SPIN_MAX=0.95` 只代表约 5% 的归一化最大输出缩减，`MOT_THST_EXPO=0.65` 影响中间段曲线，均不能单独解释当前现象。详见 [电流/电压限幅复核](/D:/Develop/QGC_for_GRobot/docs/research/weak_problem/notes/2026-08-17_motor_limit_review.md)。

进一步对照 `f3a6fa9d` 对应的 ArduSub 4.8 `AP_Motors6DOF` 源码：6DOF 电流限幅最大油门函数返回 `1.0f`；实际电流限制仅在 `MOT_BAT_CURR_MAX>0` 且电池电流可用时降低 `_output_limited`。当前配置不满足条件，因此暂未发现标准固件代码中的隐藏电流限制。自定义分支差异仍可通过 HEX 反汇编继续排查，但优先级已低于 ESC 输入响应和负载侧验证。

### H0：QGC 与固件协议/版本不兼容（当前证据不支持）

该假设已被当前连接证据显著降低优先级：MAVLink 2 心跳、完整参数下载、固件版本请求和 ArduSub 专用命名值均正常。后续只有在发现特定消息被丢弃、字段值异常或 QGC 构建时使用了不同 MAVLink 方言时，才重新打开此方向。

### H2：推进器输出上下限或协议配置造成限幅（高优先级）

重点检查：

```text
MOT_PWM_TYPE
MOT_PWM_MIN
MOT_PWM_MAX
MOT_SPIN_MAX
MOT_SLEW_UP_TIME
MOT_BAT_CURR_MAX
MOT_BAT_VOLT_MIN
MOT_BAT_VOLT_MAX
MOT_THST_EXPO
SERVO_RATE
SERVO_DSHOT_RATE
SERVO1...SERVO12_FUNCTION
SERVO1...SERVO12_MIN/MAX/TRIM/REVERSED
```

特别注意 `MOT_PWM_TYPE=8 (PWMRange)` 或 `9 (PWMAngle)` 时，输出范围可能由各路 `SERVOx_MIN/MAX` 单独决定。

### H3：飞行模式、混控或多轴同时输入导致输出归一化（中优先级）

如果单路 Motor Test 或物理 PWM 直发动力正常，但正常驾驶时动力不足，需要检查：

- `FRAME_CONFIG` 是否与实际推进器布局一致；
- 推进器功能映射及方向是否正确；
- 同时存在升沉、姿态修正、前进或偏航请求时，混控是否为防止饱和而缩放输出；
- Manual、Stabilize、Depth Hold 等模式下表现是否不同。

### H4：板级定时器组或实际 PWM 波形异常（中优先级）

如果 MAVLink/DataFlash 显示飞控已输出目标值，但 ESC 输入端实测脉宽、频率或极性不符，应转向检查：

- 同一定时器组的协议与频率；
- 物理输出口与 `SERVOx` 编号是否一致；
- PWM 信号幅度、地线参考和接口驱动；
- ESC 是否正确识别中位、最大值和反向范围。

### H5：高负载电源链路仍存在压降或限流（保留）

硬件问题虽然已基本排除，但由于飞控电源遥测不可信，仍需在高输出测试时保留以下测量：

- 电池或母线端电压；
- ESC 输入端电压；
- 总电流和单路电流（条件允许时）；
- 单推进器与多推进器同时工作的差异。

如果飞控输出已经到达目标 PWM，而高负载时电压明显下降或多推进器同时运行才变弱，应重新评估供电链路。

## 5. 计划测试矩阵

连接飞控后先备份参数，再按以下顺序测试。任何会使推进器旋转的测试都必须由现场人员确认安全后执行。

| 测试 | 输入路径 | 需要记录 | 主要用途 |
| --- | --- | --- | --- |
| A | 手柄正常驾驶，逐轴满量程 | `MANUAL_CONTROL`、`PilotGain`、`SERVO_OUTPUT_RAW`/`RCOU` | 判断手柄与摇杆增益限幅 |
| B | ArduSub Motor Test，逐路固定百分比 | 命令百分比、飞控输出、推进器表现 | 判断混控之外的电机输出链路 |
| C | QGC“推进器 PWM 直发”，逐物理口测试 | 命令 PWM、飞控输出、物理 PWM、推进器表现 | 绕过功能映射和 Motor Test 路径 |
| D | 单路与多路相同输出对比 | PWM、电源端电压、电流、转速或推力 | 判断供电压降或总电流限制 |

建议先使用低输出确认方向和接口映射，再逐步提高。不要直接从中位跳到极限。

### 结果判读

| 观察结果 | 优先排查方向 |
| --- | --- |
| 手柄弱，Motor Test 和 PWM 直发正常 | `JS_GAIN_*`、`JS_THR_GAIN`、模式或混控 |
| 手柄和 Motor Test 弱，PWM 直发正常 | `MOT_*` 限幅、PWM 类型或电机输出逻辑 |
| 三条路径都弱，且飞控输出未到目标 PWM | 通道上下限、协议、定时器组或参数限制 |
| 三条路径都弱，但物理 PWM 已到目标范围 | ESC、推进器、负载或电源链路 |
| 飞控遥测显示目标 PWM，但实测波形不符 | 板级输出、接线、地线或信号驱动 |
| 单路正常，多路同时运行明显变弱 | 电源压降、限流、接插件或电池能力 |

## 8. 安全边界

- 测试前固定机器人，清空推进器和机械结构周边；
- 高输出测试应在适合推进器工作的水中进行，并采用短时、逐级增加方式；
- 参数读取、日志下载和静态检查可以只读执行；
- 修改输出协议、PWM 上下限、功能映射或刷写固件前，先备份完整参数并记录变更；
- 不同时修改多个可能影响输出的参数，以保证测试结果可归因；
- 出现异常振动、异响、过流、明显压降、失联或不可预测输出时立即停止测试。
